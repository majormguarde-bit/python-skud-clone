# Инструкция по развертыванию проекта на Windows

Это руководство поможет вам развернуть и запустить проект СКУД-сервера на удаленном компьютере под управлением Windows.

## 1. Подготовка окружения

### 1.1. Установка Python
-   Загрузите и установите последнюю версию Python с официального сайта [python.org](https://www.python.org/downloads/windows/).
-   **Важно:** Во время установки убедитесь, что вы отметили галочку `Add Python to PATH`.

### 1.2. Установка Git
-   Загрузите и установите Git с официального сайта [git-scm.com](https://git-scm.com/download/win).
-   Это позволит вам клонировать репозиторий с проектом.

### 1.3. Клонирование репозитория
-   Откройте командную строку (`cmd` или `PowerShell`).
-   Перейдите в директорию, где вы хотите разместить проект (например, `C:\projects`).
-   Выполните команду для клонирования репозитория:
    ```bash
    git clone https://github.com/majormguarde-bit/python-skud-clone.git
    cd python-skud-clone
    ```

### 1.4. Создание и активация виртуального окружения
-   Внутри папки проекта выполните следующие команды для создания и активации виртуального окружения. Это изолирует зависимости проекта от глобальной системы.
    ```bash
    python -m venv venv
    venv\\Scripts\\activate
    ```
-   После активации в начале командной строки вы должны увидеть `(venv)`.

### 1.5. Установка зависимостей
-   Установите все необходимые библиотеки Python, перечисленные в файле `requirements.txt`:
    ```bash
    pip install -r requirements.txt
    ```

## 2. Конфигурация и запуск

### 2.1. Настройка подключения к Firebird
-   Приложение использует базу данных Firebird для синхронизации данных.
-   Откройте страницу настроек в веб-интерфейсе: `http://localhost:5000/settings`.
-   Укажите корректные параметры для подключения к вашей базе данных Firebird:
    -   **Хост** (IP-адрес сервера)
    -   **Порт** (по умолчанию 3050)
    -   **Путь к файлу базы данных** (например, `C:\DB\MY_DATABASE.FDB`)
    -   **Пользователь** (по умолчанию `sysdba`)
    -   **Пароль**

### 2.2. Запуск приложения
-   После настройки, находясь в командной строке с активированным виртуальным окружением `(venv)`, выполните команду:
    ```bash
    python run.py
    ```
-   Сервер будет запущен по адресу `http://localhost:5000`.
-   При первом запуске будет автоматически создана локальная база данных `skud_local.db` и учетная запись администратора по умолчанию:
    -   **Логин:** `admin`
    -   **Пароль:** `admin123`

## 3. (Рекомендуется) Запуск в производственной среде

Для стабильной работы в производственной среде не рекомендуется использовать встроенный сервер разработки Flask. Вместо этого следует использовать связку **Waitress** (WSGI-сервер) и **NSSM** (для запуска приложения как службы Windows).

### 3.1. Установка Waitress
-   Установите Waitress в вашем виртуальном окружении:
    ```bash
    pip install waitress
    ```

### 3.2. Создание файла для запуска
-   Создайте в корневой папке проекта файл `run_waitress.py` со следующим содержимым:
    ```python
    from app import create_app
    from waitress import serve
    import os

    app = create_app()

    if __name__ == '__main__':
        port = int(os.environ.get("PORT", 5000))
        serve(app, host='0.0.0.0', port=port)
    ```

### 3.3. Установка и настройка NSSM
-   **NSSM (Non-Sucking Service Manager)** — это утилита, которая позволяет легко создавать службы Windows из любых исполняемых файлов.
-   Загрузите последнюю версию NSSM с официального сайта [nssm.cc](https://nssm.cc/download).
-   Распакуйте архив и скопируйте `nssm.exe` (соответствующей разрядности вашей системы, 32-bit или 64-bit) в удобное место, например `C:\Windows\System32`, чтобы команда `nssm` была доступна из любой директории.

### 3.4. Создание службы Windows
-   Откройте командную строку **от имени администратора**.
-   Выполните команду для установки новой службы (например, с именем `SKUDServer`):
    ```bash
    nssm install SKUDServer
    ```
-   Откроется графический интерфейс NSSM. Укажите следующие параметры на вкладке **Application**:
    -   **Path:** Полный путь к `python.exe` в вашем виртуальном окружении. Пример: `D:\projects_2025\WEBApp\FLASK\python_skud_clone\venv\Scripts\python.exe`
    -   **Startup directory:** Полный путь к корневой папке вашего проекта. Пример: `D:\projects_2025\WEBApp\FLASK\python_skud_clone`
    -   **Arguments:** Имя файла для запуска через Waitress: `run_waitress.py`

-   Перейдите на вкладку **Details** и задайте отображаемое имя службы, например, `SKUD Web Server`.
-   Нажмите кнопку **Install service**.

### 3.5. Запуск службы
-   После установки вы можете запустить службу через стандартную оснастку "Службы" (`services.msc`) или через командную строку:
    ```bash
    nssm start SKUDServer
    ```
-   Теперь ваше приложение будет работать в фоновом режиме как полноценная служба Windows и автоматически перезапускаться при сбоях или после перезагрузки сервера.

## 4. (Опционально) Автоматический перезапуск при обновлении кода

Если вы часто обновляете код на удаленном сервере (например, для тестирования), ручной перезапуск службы может быть утомительным. Вы можете настроить автоматический перезапуск сервера при обнаружении изменений в файлах.

**Примечание:** Этот метод отлично подходит для сред разработки и тестирования. Для стабильной производственной среды рекомендуется использовать NSSM, как описано в разделе 3.

### 4.1. Установка зависимостей
-   Убедитесь, что вы установили все зависимости, включая `watchdog`:
    ```bash
    pip install -r requirements.txt
    ```

### 4.2. Запуск с автоматическим перезапуском
-   Вместо запуска службы через NSSM, вы можете запустить специальный скрипт, который будет отслеживать изменения.
-   Активируйте виртуальное окружение (`venv\Scripts\activate`) и выполните:
    ```bash
    python run_autoreload.py
    ```
-   Этот скрипт запустит ваш веб-сервер и будет следить за изменениями во всех `.py` файлах.

### 4.3. Процесс обновления
-   Теперь ваш процесс обновления на удаленном сервере становится намного проще:
    1.  Подключитесь к серверу.
    2.  Перейдите в папку проекта.
    3.  Выполните `git pull`.
-   Скрипт `run_autoreload.py` автоматически обнаружит, что файлы изменились, и сам перезапустит веб-сервер. Вам больше не нужно останавливать и запускать его вручную.
